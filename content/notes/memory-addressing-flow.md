## CPU 发出虚拟地址

CPU 核心发出的每一个访问地址，默认都是**虚拟地址（VA）**。

这个地址被拆分为两部分：

- **虚拟页号（VPN）** — 用于查映射
- **页内偏移（Offset）** — 直接透传，不参与转换

```
虚拟地址 VA = [ 虚拟页号 VPN | 页内偏移 Offset ]
```

## 地址转换：TLB 与页表

CPU 拿着虚拟地址去找**内存管理单元（MMU）**，MMU 并行去查 **TLB（快表）**。

### 1. TLB 命中（查到了记录）

TLB 是**页表的 SRAM 高速副本**，位于 CPU 内部，速度极快。

> **避坑**：TLB 命中 ≠ 数据一定在内存。如果是"标记匹配"但**有效位（V 位）= 0**（惰性失效），会直接触发缺页中断去硬盘调页。

**标准安全结论**：只有当 **"标记匹配"且"有效位 V = 1"** 时，才说明该页面确实在内存中，MMU 拼接出**物理地址（PA）**，进入下一步。

### 2. TLB 未命中（没查到记录）

CPU 去**内存（DRAM）**中查询**多级页表**（Page Table Walk，需访问内存 2～4 次）。

```
TLB 未命中 → 查多级页表
  ├─ V = 1 → 生成物理地址，回填 TLB（方便下次快速命中）
  └─ V = 0 → 触发缺页中断
```

## 物理地址取数据：Cache → 内存 → 硬盘

拿到物理地址后，CPU 去拿真正的"数据 / 指令"：

### 1. 查 Cache（高速缓存）

物理地址先去 L1 / L2 / L3 Cache 匹配：

- **Cache 命中** → 数据直接发给 CPU 寄存器，流程结束（最快）
- **Cache 未命中** → **注意：这里不去硬盘！** CPU 去主存（DRAM）读取数据，取出后回填 Cache，再发给 CPU

### 2. 什么时候去硬盘？

唯一的例外：在 TLB / 页表查询阶段，发现 **有效位 V = 0** 时，触发**缺页中断**。

此时操作系统介入，从硬盘（Swap 分区）调页进内存，更新页表和 TLB，然后重新执行刚才那条指令。

## 数据修改与写回策略

如果 CPU 修改了 Cache 中的数据，涉及写回策略：

| 特征 | 写直达法（Write-Through） | 写回法（Write-Back）— 现代CPU主流 |
|------|-------------------|-------------------------------|
| **操作时机** | 写入 Cache 时，**同时立即**写入主存 | 只写 Cache，**不写主存**，仅标记**脏位 = 1** |
| **硬件开销** | 无需脏位，实现简单 | 必须有 1 个脏位，实现复杂 |
| **性能** | 每次写操作极慢（等慢速内存） | 大多数写操作极快（纳秒级），仅被替换时才写回内存 |
| **标准搭配** | 通常搭配**非写分配**（缺失时不调入 Cache） | 通常搭配**写分配**（缺失时先调入 Cache 再修改） |

## 核心避坑指南（3 个易混淆点）

### ① TLB 是"升级版"吗？

**不是。** TLB 是页表的"高速副本"，不是替代品。TLB 查不到还得回头找页表。

### ② Cache 没命中要去硬盘吗？

**绝对不。** Cache 没命中**先去主存（内存）**。只有在**页表有效位为 0** 时才会去硬盘（触发缺页中断）。

### ③ 快表命中 = 有效位为 1 吗？

**不一定。** 物理命中只代表 Tag 匹配，如果 V = 0（惰性失效），依然会触发缺页异常。面试时务必把**"标记匹配"和"有效位为 1"** 捆绑表达才严谨。

## 终极串联流程（标准答案版）

```
CPU 发出虚拟地址
  → MMU 查 TLB（同时检查 V 位）
    → 若 TLB 未命中：去内存查多级页表
      → 若页表 V = 0：触发缺页中断，去硬盘调页，更新 TLB 后重试
    → 若 TLB 命中（且 V = 1）或页表 V = 1：拼接出物理地址
  → 拿着物理地址查 Cache
    → 命中 → 直接给 CPU
    → 未命中 → 去主存取数据，并回填 Cache
  → 若修改数据：采用写回法（标记脏位，替换时才写回主存）
```

> 一句话总结：**虚拟地址 → TLB / 页表（翻译）→ Cache / 主存（取数）→ 写回策略（改数）**。硬盘只在缺页中断时才参与，Cache 未命中永远先去主存。
