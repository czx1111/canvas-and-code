## 核心基础概念

| 术语 | 定义 | 关键点 |
| :--- | :--- | :--- |
| **页（Page）** | 进程虚拟地址空间划分的块 | 逻辑上的，大小固定（如 4KB） |
| **页框（Page Frame）** | 物理内存划分的块 | 物理上的，**大小 = 页大小** |
| **页表** | 记录页→页框映射关系的表 | 每个进程一张 |
| **缺页中断** | 访问的页不在内存中 | 需要从磁盘换入 |
| **驻留集** | 进程**当前实际**在内存中的页框集合 | 大小 = 分配给该进程的页框数 |
| **工作集** | 进程在**某段时间 Δ 内**频繁访问的页面集合 | 决定进程顺畅运行的最低内存需求 |

> **黄金法则**：驻留集 ≥ 工作集 → 进程缺页率低，运行顺畅。

---

## 进程分配多少页框？

操作系统采用以下 **3 种策略**之一：

| 分配策略 | 页框数量变化 | 缺页时从哪淘汰？ |
| :--- | :--- | :--- |
| **固定分配局部置换** | 进程创建时固定，**不变** | 从该进程自己的页框里淘汰一个 |
| **可变分配全局置换** | **动态增加/减少** | 从**所有进程**（全局）中抢一个页框回收 |
| **可变分配局部置换** | 有上限，动态增加 | 缺页时优先淘汰**该进程自己**的页 |

## 页面置换算法

按**性能从优到劣**（以及考频）排列：

| 算法 | 淘汰依据 | 是否可实现？ | 是否发生 Belady 异常？ | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| **OPT（最佳）** | 未来最长时间不用的页 | ❌ 不能（需预知未来） | **否** | 仅作**性能标杆** |
| **LRU（最近最久未用）** | 过去最久没用的页 | ✅ 能（需硬件栈/计数器） | **否** | 性能最接近 OPT，但硬件开销大 |
| **改进型 CLOCK** | 看 **(A, M)** 四类 | ✅ 能（硬件位） | **否**（本质上近似 LRU） | 淘汰次序：**(0,0)→(0,1)→(1,0)→(1,1)** |
| **基础 CLOCK（二次机会）** | 只看 **A（访问位）** | ✅ 能（硬件位） | 教材默认没有 | 指针循环扫描，A=1 置 0 给机会 |
| **FIFO（先进先出）** | 在内存中**驻留最久** | ✅ 最简单 | **是（唯一主角）** | 性能最差，但实现最简单 |


### 各算法详解

**OPT（最佳置换）**：淘汰未来最长时间不会被访问的页面。由于无法预知未来的访问序列，仅作为理论标杆，用于评估其他算法的优劣。

**LRU（最近最久未使用）**：淘汰过去最久未被访问的页面。实现方式包括寄存器栈（每次访问将页面移到栈顶，淘汰栈底）和计数器法（每个页面维护一个计数器）。性能优秀，但需要硬件支持，开销较大。

**FIFO（先进先出）**：淘汰最先进入内存的页面。实现简单（维护一个队列），但存在 Belady 异常——分配更多页框反而可能增加缺页率。

**CLOCK（二次机会）**：FIFO 的改进版。所有页面组成环形链表，指针依次扫描。遇到访问位 A=0 的页面就淘汰；遇到 A=1 的页面，将其置 0 并跳过（给予"二次机会"）。

**改进型 CLOCK**：在访问位 A 的基础上增加修改位 M，形成四类页面 (A, M)：
1. (0, 0) — 未访问未修改，最佳淘汰对象
2. (0, 1) — 未访问已修改，淘汰前需写回磁盘
3. (1, 0) — 已访问未修改，首轮扫过时 A 置 0
4. (1, 1) — 已访问已修改，最差淘汰对象

## 抖动（Thrashing）

**定义**：进程频繁缺页，CPU 大部分时间在等磁盘 I/O，几乎不执行指令。

**表象**：CPU 利用率**骤降**，磁盘交换区灯狂闪。

**根本原因**：**多道程序并发度过高**（同时跑的进程太多），导致每个进程分到的驻留集 **<** 自己的工作集。

**解决方案**：

1. **降低多道程序度**（挂起部分进程）
2. 增加物理内存（硬件扩容）
3. 采用**工作集模型**，动态监控缺页频率并调整页框分配

---

## Belady 异常

**定义**：给进程分配的**页框数增加**，缺页次数**反而增加**。

**触发条件**：**只有 FIFO 算法**会出现。

**为什么 LRU/OPT 不会？**

因为它们是**栈式算法**（具有包含性）：n 个页框时的驻留集，一定是 n+1 个页框时驻留集的子集。内存越大，有用页面越不会被挤出去，缺页率只降不升。

---

## 逻辑链条

1. 物理内存被划分成**页框**，进程虚拟内存被划分成**页**。
2. OS 根据**固定/可变策略**给进程分配若干页框（**驻留集**）。
3. 若进程访问的页不在内存 → **缺页中断**。
4. 若驻留集已满，需调用**置换算法**（FIFO/LRU/CLOCK 等）淘汰旧页。
5. 若分配的驻留集 **<** 进程的**工作集** → 频繁缺页 → **抖动**。
6. 若此时采用 **FIFO** 算法，增加页框不仅解决不了抖动，反而引发 **Belady 异常**（缺页率不降反升）。
