## 基础概念层

### 进程状态与信号量

在操作系统中，进程分为**就绪、运行、阻塞**三个基本工作状态（还有创建态、结束态）。三种状态在特定条件下可以相互转换，而信号量机制是实现这种转换控制的核心工具。

**PV 操作**（荷兰语 Proberen/Verhogen）：
- **P 操作**：申请资源（wait）
- **V 操作**：释放资源（signal）

### 为什么需要信号量？

进程不能随便申请资源，否则可能造成**死锁**。信号量通过两种关系来规范资源申请：

| 关系类型 | 定义 | 信号量初始值 |
|---------|------|-------------|
| **互斥** | 资源只能分配给一个进程 | 1 |
| **同步** | 等待进程A完成后才执行进程B | 0 |

### 基本模式

#### 同步操作

```c
semaphore ready = 0;  // 初始信号量为0

// 进程A
准备好数据;
V(ready);  // 通知：我准备好了

// 进程B
P(ready);  // 等待：直到有人通知我
处理数据;
```

#### 互斥操作

```c
semaphore mutex = 1;  // 初始信号量为1，表示最多允许一个进程访问共享资源

进程 {
    P(mutex);  // 申请使用资源，若其他进程在使用则申请不到
    临界区（访问共享资源）;
    V(mutex);  // 处理完后释放资源
}
```

## 经典 PV 操作问题

### 1. 生产者-消费者模型

**关联分析**：既有**互斥**（缓冲区不能同时读写），又有**同步**（缓冲区满时生产者要等消费者取；缓冲区空时消费者要等生产者放）。

**信号量定义**：
- `empty` = n（空闲位置数，初始为缓冲区大小）
- `full` = 0（产品数量，初始为0）
- `mutex` = 1（缓冲区互斥锁）

```c
// 生产者
Producer {
    while(1) {
        生产一个产品;
        P(empty);     // ① 申请一个空闲位置，若满则阻塞
        P(mutex);     // ② 申请进入缓冲区（锁门）
        把产品放入缓冲区;
        V(mutex);     // ③ 释放缓冲区（开门）
        V(full);      // ④ 通知消费者，产品数量+1
    }
}

// 消费者
Consumer {
    while(1) {
        P(full);      // ① 申请一个产品，若空则阻塞（等通知）
        P(mutex);     // ② 申请进入缓冲区（锁门）
        从缓冲区取出产品;
        V(mutex);     // ③ 释放缓冲区（开门）
        V(empty);     // ④ 通知生产者，空闲位置+1
        消费该产品;
    }
}
```

> **关键点**：`P(empty)` 和 `P(full)` **必须放在 `P(mutex)` 外面**！如果先锁门再等资源，会导致自己抱着锁睡觉，别人进不来，造成**死锁**。

### 2. 哲学家就餐问题（防死锁版）

**关联分析**：纯互斥（一根筷子只能被一个人拿）。但如果不加限制，5个人同时拿起左边的筷子，就全卡死了（循环等待）。

**解决方案**：限制同时就餐人数，最多只允许 n-1 个人同时抢筷子。

**信号量定义**：
- `chopstick[5]` = {1,1,1,1,1}（每根筷子互斥）
- `room` = 4（哲学家人数5，限制最多4人同时进入"抢筷子"状态）

```c
Philosopher_i (i=0~4) {
    while(1) {
        思考;
        P(room);                // ① 申请进入"就餐候选区"，人数满4则门外等
        P(chopstick[i]);        // ② 拿起左边的筷子
        P(chopstick[(i+1)%5]);  // ③ 拿起右边的筷子
        吃饭;
        V(chopstick[i]);        // ④ 放下左边
        V(chopstick[(i+1)%5]);  // ⑤ 放下右边
        V(room);                // ⑥ 离开候选区，让门外的人进来
    }
}
```

> **关键点**：`room` 信号量保证最多4个人参与抢筷子，总会有一个人能拿到两根，吃完释放，从而打破死锁。

### 3. 理发师问题（带等待椅子的睡眠理发师）

**关联分析**：同步（顾客来了叫醒理发师，理发师理完叫下一个）。难点在于**理发师没顾客时会睡觉**，**顾客进来发现没位置就走**。

**信号量定义**：
- `customers` = 0（等待的顾客数量，初始0）
- `barbers` = 0（空闲理发师数量，初始0，因为理发师初始在睡觉）
- `mutex` = 1（对共享变量 `waiting_count` 的互斥）
- 假设有 `n` 把等候椅子

```c
// 理发师
Barber {
    while(1) {
        P(customers);      // ① 尝试叫一个顾客，如果没有则睡觉（阻塞）
        P(mutex);
        waiting_count--;   // 修改等待人数
        V(mutex);
        V(barbers);        // ② 通知顾客"我来给你理发了"
        给顾客理发;
    }
}

// 顾客
Customer {
    P(mutex);
    if (waiting_count < n) {  // 有空椅子
        waiting_count++;
        V(mutex);
        V(customers);      // ③ 叫醒理发师（如果他在睡）
        P(barbers);        // ④ 等待理发师空闲（如果理发师忙，先排队等）
        接受理发;
    } else {
        V(mutex);          // 没座位，直接离开
    }
}
```

> **关键点**：顾客流程是**先 V(customers) 叫醒理发师，再 P(barbers) 等理发师**；理发师流程是**先 P(customers) 等顾客，再 V(barbers) 通知顾客**。这两个V和P交叉呼应，实现了双向握手。

### 4. 读者-写者问题（读者优先）

**关联分析**：读者之间**不互斥**（可同时读），但写者与其他任何人**互斥**（写时不能读，读时不能写）。

**信号量定义**：
- `rw_mutex` = 1（读写互斥信号量，写者独占，第一个读者拿，最后一个读者放）
- `mutex` = 1（保护读者计数器 `read_count` 的互斥锁）
- `read_count` = 0（当前读者数量）

```c
// 写者
Writer {
    while(1) {
        P(rw_mutex);    // 申请写权限（独占），若有读者在等则阻塞
        写数据;
        V(rw_mutex);    // 释放写权限
    }
}

// 读者
Reader {
    while(1) {
        P(mutex);           // ① 锁住计数器
        if (read_count == 0) 
            P(rw_mutex);    // ② 第一个读者来，阻止写者进入
        read_count++;
        V(mutex);           // ③ 释放计数器
        读数据;  // 此时其他读者可以并发读，写者进不来
        P(mutex);
        read_count--;
        if (read_count == 0) 
            V(rw_mutex);    // ④ 最后一个读者走，放行写者
        V(mutex);
    }
}
```

> **关键点**：`P(rw_mutex)` 是由**第一个读者**申请的，由**最后一个读者**释放的。这种模式会导致**写者饥饿**（如果读者源源不断，写者永远抢不到）。若要"写者优先"或"公平读写"，则需要再加一个信号量控制排队顺序，逻辑会更复杂。

## 核心原则总结

### 1. 同步（一前一后）
P 操作放在**等待事件**的前面，V 操作放在**产生事件**的后面。
- 如：生产者放完 `V(full)`，消费者开头 `P(full)`

### 2. 互斥（独占资源）
P 和 V 必须**紧挨着**夹住临界区，中间不能有别的 P 操作，否则容易死锁。

### 3. 信号量初始值

| 类型 | 初始值 |
|-----|--------|
| 资源数量（缓冲区大小、筷子数量） | n |
| 状态标志（是否有数据、是否有顾客） | 0 |
| 互斥锁 | 1 |

---

> 一句话总结：**同步用 P 等前 V 发后，互斥用 PV 夹临界区；资源数量初始 n，状态标志初始 0，互斥锁初始 1。**
